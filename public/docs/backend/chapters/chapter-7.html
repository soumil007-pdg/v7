🛡️ Chapter 7: Authorization & Access Control

Authentication proves WHO you are. Authorization decides WHAT you can do. This chapter covers controlling access to protected resources.

Authentication vs Authorization

Authentication Authorization
Are you who you claim? What are you allowed to do?
Login with email/password Can access /dashboard?
"Prove you're John" "What can John do?"

Protecting Routes

Some endpoints should only work if you're logged in:

// app/api/chat/route.js (Protected - requires login)
export async function POST(request) {
  // Get token from header
  const authHeader = request.headers.get('Authorization');
  const token = authHeader?.replace('Bearer ', '');

  if (!token) {
    return Response.json(
      { error: 'Authentication required' },
      { status: 401 }  // Unauthorized
    );
  }

  // Validate token
  const session = sessions.get(token);
  if (!session) {
    return Response.json(
      { error: 'Invalid token' },
      { status: 401 }
    );
  }

  // User is authenticated! Continue...
  const userId = session.userId;
  const user = users.get(userId);

  console.log(`${user.email} is using chat`);
  return Response.json({ success: true });
}

Role-Based Access Control (RBAC)

Different users have different roles (admin, user, lawyer):

// User data with role
users.set('user-1', {
  id: 'user-1',
  email: 'admin@example.com',
  role: 'admin',  // Can do everything
  password: '...'
});

users.set('user-2', {
  id: 'user-2',
  email: 'lawyer@example.com',
  role: 'lawyer',  // Can see cases
  password: '...'
});

users.set('user-3', {
  id: 'user-3',
  email: 'client@example.com',
  role: 'user',    // Limited access
  password: '...'
});

Checking Roles

// app/api/admin/stats/route.js (Admin only)
export async function GET(request) {
  const token = getToken(request);
  const session = validateToken(token);

  if (!session) {
    return Response.json({ error: 'Unauthorized' }, { status: 401 });
  }

  const user = users.get(session.userId);

  // Check if admin
  if (user.role !== 'admin') {
    return Response.json(
      { error: 'Admin access required' },
      { status: 403 }  // Forbidden
    );
  }

  // User is admin! Return stats
  return Response.json({
    totalUsers: users.size,
    totalSessions: sessions.size
  });
}

Resource-Level Authorization

Users can only access their own data:

// User can only see their own profile
// GET /api/user/profile/:userId

export async function GET(request) {
  const token = getToken(request);
  const session = validateToken(token);

  if (!session) {
    return Response.json({ error: 'Unauthorized' }, { status: 401 });
  }

  // Get requested user ID from URL
  const url = new URL(request.url);
  const requestedUserId = url.pathname.split('/').pop();

  // Check: Can THIS user access THAT user's data?
  if (session.userId !== requestedUserId) {
    return Response.json(
      { error: 'Cannot access other users data' },
      { status: 403 }
    );
  }

  // User is requesting their own data
  const user = users.get(requestedUserId);
  return Response.json({
    id: user.id,
    email: user.email
  });
}

HTTP Status Codes for Access

Code Meaning When
401 Unauthorized Not logged in / invalid token
403 Forbidden Logged in but don't have permission
404 Not Found Resource doesn't exist

Middleware for Authorization

Check authentication for multiple routes at once:

// middleware.js
export function middleware(request) {
  const path = request.nextUrl.pathname;

  // Routes that require authentication
  const protectedRoutes = [
    '/api/chat',
    '/api/case-advisor',
    '/api/user/profile'
  ];

  const isProtected = protectedRoutes.some(route => path.startsWith(route));

  if (isProtected) {
    const token = request.headers.get('Authorization')?.replace('Bearer ', '');

    if (!token) {
      return Response.json({ error: 'No token' }, { status: 401 });
    }

    // Continue if token is valid
  }

  return null;  // Continue normally
}

Audit Logging

Track who did what (for security):

const auditLog = [];

function logAction(userId, action, resource) {
  auditLog.push({
    userId,
    action,
    resource,
    timestamp: Date.now()
  });
}

// In protected route
export async function POST(request) {
  const token = getToken(request);
  const session = validateToken(token);
  const userId = session.userId;

  // Do the action
  logAction(userId, 'DELETE', 'case-123');

  return Response.json({ success: true });
}

Common Authorization Patterns

  • Public: No authentication needed
  • Authenticated: Must be logged in
  • Role-based: Must have specific role (admin, lawyer)
  • Owner-only: Can only access own data
  • Admin-only: Only administrators

Key Concepts

  • Authorization: Deciding what users can do
  • Role: User classification (admin, user, lawyer)
  • 401: Unauthorized (not logged in)
  • 403: Forbidden (logged in but no permission)
  • Audit log: Recording who did what
