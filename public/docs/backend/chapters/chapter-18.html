Complete Request Flow: Login

1. USER CLICKS LOGIN
   ├─ Frontend: Takes email & password
   ├─ Frontend: POST /api/auth/login
   └─ Frontend: Sends { email, password }

2. MIDDLEWARE RUNS
   ├─ Check locale
   ├─ Log request
   └─ Continue to route handler

3. LOGIN ROUTE HANDLER
   ├─ Extract email & password from body
   ├─ Validate: Not empty? Valid email?
   ├─ Find user by email (in authStore.users)
   ├─ Compare password with hash (bcryptjs)
   └─ If valid: Continue. If not: Return 401

4. CREATE SESSION
   ├─ Generate unique token (UUID)
   ├─ Store in sessions Map
   ├─ Set expiry (24 hours)
   └─ Prepare response

5. RETURN RESPONSE
   ├─ Status: 200 OK
   ├─ Body: { success: true, token: "..." }
   └─ Frontend receives token

6. FRONTEND STORES TOKEN
   ├─ Save to localStorage
   ├─ Redirect to dashboard
   └─ User is logged in!

Complete Request Flow: Chat

1. USER SENDS MESSAGE
   ├─ Frontend: User types message
   ├─ Frontend: POST /api/chat
   ├─ Includes: Authorization header with token
   └─ Includes: { message: "What's copyright law?" }

2. MIDDLEWARE RUNS
   ├─ Check locale
   ├─ Continue to handler

3. CHAT ROUTE HANDLER
   ├─ Extract token from Authorization header
   ├─ Validate token exists
   ├─ Check if token in sessions Map
   ├─ Get userId from session
   ├─ Find user data from userId
   └─ If invalid: Return 401

4. RATE LIMITING
   ├─ Check: Did user exceed limit?
   ├─ Limit: 50 messages per hour
   └─ If exceeded: Return 429

5. CALL GEMINI AI
   ├─ Prepare system instruction (legal expert)
   ├─ Include conversation history (if any)
   ├─ Send message to Gemini API
   ├─ Gemini thinks and responds
   └─ Get response text

6. SAVE CONVERSATION
   ├─ Store in conversations Map
   ├─ Add user message
   ├─ Add AI response
   ├─ Update timestamp

7. RETURN RESPONSE
   ├─ Status: 200 OK
   ├─ Body: { success: true, response: "..." }
   ├─ Include rate limit headers
   └─ Frontend displays response to user

Complete Request Flow: Case Advisor

1. USER FILLS FORM
   ├─ Enters case title
   ├─ Describes situation
   ├─ Selects category (civil, criminal, etc.)
   ├─ Asks legal question
   └─ Clicks "Get Advice"

2. FRONTEND VALIDATES
   ├─ All fields filled?
   ├─ Valid email format?
   └─ POST /api/case-advisor

3. MIDDLEWARE RUNS
   ├─ Check locale
   └─ Continue

4. CASE ADVISOR HANDLER
   ├─ Extract case data from body
   ├─ Get token from Authorization header
   ├─ Validate token (same as chat)
   ├─ Validate case data
   │  ├─ Title not empty?
   │  ├─ Description not empty?
   │  ├─ Legal query not empty?
   │  └─ If invalid: Return 400
   └─ Continue if valid

5. RATE LIMITING
   ├─ Strict limit: 5 per hour (expensive)
   ├─ Check user's count
   └─ If exceeded: Return 429

6. CREATE CASE
   ├─ Generate case ID
   ├─ Store in cases Map
   ├─ Associate with user
   └─ Set status to "open"

7. CALL GEMINI
   ├─ Build detailed prompt
   ├─ Include case details
   ├─ Include legal question
   ├─ Request structured analysis
   ├─ Send to Gemini
   └─ Get legal analysis

8. SAVE ANALYSIS
   ├─ Store analysis in case
   ├─ Update case status
   ├─ Record timestamp

9. RETURN RESPONSE
   ├─ Status: 200 OK
   ├─ Body: { caseId, analysis, ... }
   └─ Frontend displays advice

Error Scenarios

SCENARIO 1: User tries login with wrong password
├─ Frontend: POST /api/auth/login
├─ Route: Find user ✓
├─ Route: Hash password, compare ✗
├─ Route: Return 401 Unauthorized
└─ Frontend: Show "Invalid credentials"

SCENARIO 2: User tries chat without token
├─ Frontend: POST /api/chat (no Authorization header)
├─ Route: Check Authorization header ✗
├─ Route: Return 401 Unauthorized
└─ Frontend: Redirect to login

SCENARIO 3: User exceeds rate limit
├─ Frontend: POST /api/chat (50th message)
├─ Route: Check rate limit ✗
├─ Route: Return 429 Too Many Requests
└─ Frontend: Show "Try again later"

SCENARIO 4: Gemini API is down
├─ Frontend: POST /api/chat
├─ Route: Call Gemini API ✗ (503)
├─ Route: Return 503 Service Unavailable
└─ Frontend: Show "Service temporarily down"

SCENARIO 5: Invalid request data
├─ Frontend: POST /api/chat with empty message
├─ Route: Validate data ✗
├─ Route: Return 400 Bad Request
└─ Frontend: Show validation error

Security Checklist

  • ✅ Hash passwords with bcryptjs (never store plain text)
  • ✅ Validate all user input
  • ✅ Check authentication on protected routes
  • ✅ Check authorization (user can only access their own data)
  • ✅ Use HTTPS in production
  • ✅ Store API keys in environment variables
  • ✅ Rate limit to prevent abuse
  • ✅ Log errors for debugging
  • ✅ Set token expiration
  • ✅ Clean up expired sessions

Performance Checklist

  • ✅ Cache expensive API responses
  • ✅ Rate limit API calls to external services
  • ✅ Validate before expensive operations
  • ✅ Return quickly (don't block on slow operations)
  • ✅ Use streaming for large responses
  • ✅ Implement timeout for external API calls
  • ✅ Retry failed requests with backoff

Deployment Checklist

  • ✅ Environment variables set (API keys, secrets)
  • ✅ HTTPS enabled
  • ✅ Rate limiting configured
  • ✅ Error logging enabled
  • ✅ Database/storage configured
  • ✅ CORS headers set
  • ✅ Monitoring & alerts configured

Key Takeaways

  • Use tokens for authentication (store in headers)
