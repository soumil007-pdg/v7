🗄️ Chapter 15: Database Design & Models

Data is the heart of any application. Let's learn how to structure it effectively. ADVOCAT-Easy currently uses in-memory storage, but the patterns apply to databases too.

What is a Database?

A database is organized storage for data. Types:

  • Relational (SQL): Tables with rows and columns (PostgreSQL, MySQL)
  • NoSQL (Document): Flexible JSON-like documents (MongoDB, Firebase)
  • In-Memory: Data in RAM (Redis, our authStore)

User Model

// A user should have:
{
  id: string,              // Unique identifier
  email: string,           // Email address (unique)
  password: string,        // Hashed password
  name: string,            // Full name
  role: 'user' | 'lawyer' | 'admin',  // User type
  createdAt: number,       // Creation timestamp
  updatedAt: number,       // Last modified
  lastLogin: number,       // Last login timestamp
  isActive: boolean        // Account active?
}

// Example:
{
  id: 'uuid-123',
  email: 'john@example.com',
  password: '$2b$10$...',
  name: 'John Doe',
  role: 'user',
  createdAt: 1704067200000,
  updatedAt: 1704067200000,
  lastLogin: null,
  isActive: true
}

Implementing Models with Maps

// lib/db.js
export const users = new Map();
export const cases = new Map();
export const conversations = new Map();
export const lawyers = new Map();

// Create user
export function createUser(data) {
  const user = {
    id: crypto.randomUUID(),
    email: data.email,
    password: data.password,
    name: data.name,
    role: 'user',
    createdAt: Date.now(),
    updatedAt: Date.now(),
    lastLogin: null,
    isActive: true
  };

  users.set(user.id, user);
  return user;
}

// Get user by email
export function getUserByEmail(email) {
  return Array.from(users.values()).find(u => u.email === email);
}

// Update user
export function updateUser(userId, updates) {
  const user = users.get(userId);
  if (!user) return null;

  const updated = {
    ...user,
    ...updates,
    updatedAt: Date.now()
  };

  users.set(userId, updated);
  return updated;
}

// Delete user
export function deleteUser(userId) {
  return users.delete(userId);
}

Data Validation

// lib/validation.js
export function validateUserData(data) {
  const errors = [];

  // Email validation
  if (!data.email) {
    errors.push('Email is required');
  } else if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(data.email)) {
    errors.push('Email is invalid');
  }

  // Password validation
  if (!data.password) {
    errors.push('Password is required');
  } else if (data.password.length < 6) {
    errors.push('Password must be at least 6 characters');
  }

  // Name validation
  if (!data.name) {
    errors.push('Name is required');
  } else if (data.name.length < 2) {
    errors.push('Name must be at least 2 characters');
  }

  return {
    valid: errors.length === 0,
    errors
  };
}

Indexing for Performance

For large datasets, create indexes for fast lookups:

// Create an email index
const emailIndex = new Map();

export function addUserWithIndex(user) {
  users.set(user.id, user);
  emailIndex.set(user.email, user.id);  // Fast email lookup
}

// Fast email lookup (O(1) instead of O(n))
export function getUserByEmail(email) {
  const userId = emailIndex.get(email);
  return userId ? users.get(userId) : null;
}

Migrations

When changing data structure, you need migrations:

// Before: User had firstName, lastName
// After: User has name

export function migrateUsers() {
  for (const user of users.values()) {
    if (user.firstName && user.lastName) {
      user.name = `${user.firstName} ${user.lastName}`;
      delete user.firstName;
      delete user.lastName;
    }
  }
  console.log('Migration complete');
}

Key Concepts

  • Model: Structure of data (what fields)
  • Schema: Definition of model fields
  • Relationship: How data connects (1-to-many, many-to-many)
  • Index: Fast lookup structure
  • Validation: Ensuring data is correct
  • Migration: Changing schema over time
