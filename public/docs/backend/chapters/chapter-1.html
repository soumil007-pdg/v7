🏗️ Chapter 1: Backend Basics & Architecture

Welcome to backend development! In this chapter, we'll explore what a backend is, how it works with the frontend, and the overall architecture of ADVOCAT-Easy's backend.

What is a Backend?

A backend is the server-side code that handles:

  • Data Processing — Processing form submissions, validating data
  • Business Logic — Core application rules and workflows
  • Authentication — Managing user login and sessions
  • Database Operations — Storing and retrieving data
  • External Integrations — Connecting to third-party APIs

Frontend vs Backend

Aspect Frontend Backend
Runs on User's browser Server (our computer)
Language JavaScript/React Node.js (JavaScript)
Visibility User can inspect (DevTools) Hidden from users
Security Data visible to users Keep secrets safe here

How a Request Works

Example: User logs in

  1. Frontend: User enters email & password in the login form
  2. Frontend: Clicks "Login" button → sends POST request to /api/auth/login
  3. Backend: Receives the request
  4. Backend: Validates email & password
  5. Backend: Checks database for the user
  6. Backend: If valid, creates a session token
  7. Backend: Sends response with token back to frontend
  8. Frontend: Receives token, stores it, redirects to dashboard
  9. User: Sees the dashboard (now logged in!)

API Routes in Next.js

ADVOCAT-Easy backend is built using Next.js API Routes. Instead of a separate server, we use:

app/api/[route]/route.js

This file automatically becomes an endpoint:

  • app/api/auth/login/route.js → POST http://localhost:3000/api/auth/login
  • app/api/chat/route.js → POST http://localhost:3000/api/chat
  • app/api/auth/validate/route.js → POST http://localhost:3000/api/auth/validate

Key Concepts

  • Endpoints: URLs that handle requests (like `/api/auth/login`)
  • Requests: Data sent FROM frontend TO backend
  • Responses: Data sent BACK from backend to frontend
  • Tokens: Unique strings to verify user identity
  • Sessions: Keeping track of who is logged in
  • Validation: Checking that data is correct before processing
