💾 Chapter 6: Session Management (In-Memory Store)

A session is a record on the server that says "this token belongs to this user." ADVOCAT-Easy uses an in-memory Map to store sessions.

What is a Session?

A session links a token to a user:

// When user logs in, create a session
token: 'abc123-token'  ← This token belongs to...
userId: 'user-999'     ← This user

// When user sends token in request, lookup the session
const token = request.headers.get('Authorization').replace('Bearer ', '');
const session = sessions.get(token);  // { userId: 'user-999', ... }
const user = users.get(session.userId);  // Get user data

In-Memory Store Structure

// lib/authStore.js
export const users = new Map();
export const sessions = new Map();

// Users: userId → user data
users.set('user-123', {
  id: 'user-123',
  email: 'john@example.com',
  password: '$2b$10$hashed...',
  createdAt: 1234567890
});

// Sessions: token → session data
sessions.set('token-abc', {
  userId: 'user-123',
  createdAt: 1234567890,
  expiresAt: 1234567890 + 86400000  // 24 hours later
});

Creating a Session at Login

// app/api/auth/login/route.js
import crypto from 'crypto';
import { users, sessions } from '@/lib/authStore';

export async function POST(request) {
  const { email, password } = await request.json();

  // Find user and validate password (see chapter 5)
  const user = Array.from(users.values()).find(u => u.email === email);
  const passwordValid = await bcrypt.compare(password, user.password);

  if (!passwordValid) {
    return Response.json({ error: 'Invalid credentials' }, { status: 401 });
  }

  // Create unique token
  const token = crypto.randomUUID();

  // Store session
  sessions.set(token, {
    userId: user.id,
    createdAt: Date.now(),
    expiresAt: Date.now() + 24 * 60 * 60 * 1000  // 24 hours
  });

  return Response.json({
    success: true,
    token: token
  });
}

Validating a Session

// Helper function to validate token
export function validateSession(token) {
  const session = sessions.get(token);

  if (!session) {
    return { valid: false, error: 'Token not found' };
  }

  // Check expiration
  if (Date.now() > session.expiresAt) {
    sessions.delete(token);  // Clean up expired session
    return { valid: false, error: 'Token expired' };
  }

  return { valid: true, session };
}

Using Sessions in Protected Routes

// app/api/chat/route.js (protected endpoint)
import { validateSession } from '@/lib/auth';

export async function POST(request) {
  // Get token from header
  const authHeader = request.headers.get('Authorization');
  const token = authHeader?.replace('Bearer ', '');

  if (!token) {
    return Response.json({ error: 'No token provided' }, { status: 401 });
  }

  // Validate session
  const { valid, session, error } = validateSession(token);

  if (!valid) {
    return Response.json({ error }, { status: 401 });
  }

  // Now we know who the user is!
  const userId = session.userId;
  const user = users.get(userId);

  // Process the chat message for this user
  console.log(`Chat from ${user.email}: ...`);

  return Response.json({ success: true });
}

Session Expiration

// Clean up expired sessions periodically
setInterval(() => {
  const now = Date.now();

  // Find and delete expired sessions
  for (const [token, session] of sessions.entries()) {
    if (session.expiresAt < now) {
      sessions.delete(token);
      console.log('Cleaned up expired session:', token);
    }
  }
}, 60000);  // Check every minute

Logout (Destroy Session)

// app/api/auth/logout/route.js
import { sessions } from '@/lib/authStore';

export async function POST(request) {
  const { token } = await request.json();

  // Delete the session
  const deleted = sessions.delete(token);

  if (!deleted) {
    return Response.json(
      { error: 'Session not found' },
      { status: 404 }
    );
  }

  return Response.json({
    success: true,
    message: 'Logged out'
  });
}

Session Timeout

Sessions can be "sliding" (reset expiry on activity) or "absolute" (expire after fixed time):

// Sliding expiration (reset on each request)
export function refreshSession(token) {
  const session = sessions.get(token);
  if (session) {
    session.expiresAt = Date.now() + 24 * 60 * 60 * 1000;  // Reset timer
  }
}

// Use in protected routes
validateSession(token);
refreshSession(token);  // Reset expiration

In-Memory vs Database

In-Memory (Current) Database (Future)
Data lost on server restart Data persists
Fast (data in RAM) Slower (disk I/O)
Good for development Good for production
Can't scale across servers Works across multiple servers

Key Concepts

  • Session: Server-side record linking token to user
  • Token: Unique string sent by client
  • Expiration: Sessions expire for security
  • In-Memory: Sessions stored in RAM (fast but temporary)
  • Cleanup: Expired sessions should be deleted
