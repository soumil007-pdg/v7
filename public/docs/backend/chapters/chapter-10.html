📐 Chapter 10: RESTful API Design Principles

REST is a standard way to design APIs. It makes APIs predictable and easy to use. Let's learn the principles.

What is REST?

REST = Representational State Transfer. It's a set of rules for designing APIs.

REST Principles:
1. Resources are identified by URLs
2. Operations use HTTP methods (GET, POST, PUT, DELETE)
3. Responses are stateless
4. Standard response formats (JSON)

Resources and URLs

Each URL represents a resource:

/api/users              ← Collection of users
/api/users/123          ← Specific user (ID 123)
/api/cases              ← Collection of cases
/api/cases/456          ← Specific case (ID 456)
/api/users/123/cases    ← User 123's cases

HTTP Methods (CRUD)

Method Operation Example
GET Read GET /api/users/123
POST Create POST /api/users
PUT Update PUT /api/users/123
DELETE Delete DELETE /api/users/123

RESTful Examples

// Get all users
GET /api/users
Response: [{ id: 1, name: "John" }, ...]

// Get specific user
GET /api/users/1
Response: { id: 1, name: "John", email: "john@example.com" }

// Create new user
POST /api/users
Body: { name: "Jane", email: "jane@example.com" }
Response: { id: 2, name: "Jane", ... }

// Update user
PUT /api/users/1
Body: { name: "John Updated" }
Response: { id: 1, name: "John Updated", ... }

// Delete user
DELETE /api/users/1
Response: { success: true }

Status Codes (REST)

Code Meaning When
200 OK Success (GET, PUT, DELETE)
201 Created Resource created (POST)
204 No Content Success with no data (DELETE)
400 Bad Request Invalid data
401 Unauthorized Not logged in
404 Not Found Resource doesn't exist
500 Server Error Unexpected error

Example: User API

// GET /api/users (list all)
export async function GET(request) {
  const userList = Array.from(users.values());
  return Response.json(userList, { status: 200 });
}

// POST /api/users (create new)
export async function POST(request) {
  const { name, email } = await request.json();

  if (!name || !email) {
    return Response.json(
      { error: 'Name and email required' },
      { status: 400 }
    );
  }

  const newUser = {
    id: crypto.randomUUID(),
    name,
    email,
    createdAt: Date.now()
  };

  users.set(newUser.id, newUser);

  return Response.json(newUser, { status: 201 });
}

Example: Specific User

// GET /api/users/[id] (get one)
export async function GET(request, { params }) {
  const { id } = await params;
  const user = users.get(id);

  if (!user) {
    return Response.json(
      { error: 'User not found' },
      { status: 404 }
    );
  }

  return Response.json(user, { status: 200 });
}

// PUT /api/users/[id] (update)
export async function PUT(request, { params }) {
  const { id } = await params;
  const user = users.get(id);

  if (!user) {
    return Response.json(
      { error: 'User not found' },
      { status: 404 }
    );
  }

  const updates = await request.json();
  const updated = { ...user, ...updates };
  users.set(id, updated);

  return Response.json(updated, { status: 200 });
}

// DELETE /api/users/[id] (delete)
export async function DELETE(request, { params }) {
  const { id } = await params;

  if (!users.has(id)) {
    return Response.json(
      { error: 'User not found' },
      { status: 404 }
    );
  }

  users.delete(id);
  return Response.json({ success: true }, { status: 204 });
}

Response Consistency

Always return responses in a consistent format:

// Successful response
{
  success: true,
  data: { ... }
}

// Error response
{
  success: false,
  error: "What went wrong",
  errorCode: "USER_NOT_FOUND"
}

// List response
{
  success: true,
  data: [{ ... }, { ... }],
  count: 2,
  page: 1,
  totalPages: 5
}

Filtering and Pagination

// GET /api/users?page=1&limit=10&role=admin
export async function GET(request) {
  const url = new URL(request.url);
  const page = parseInt(url.searchParams.get('page')) || 1;
  const limit = parseInt(url.searchParams.get('limit')) || 10;
  const role = url.searchParams.get('role');

  let results = Array.from(users.values());

  // Filter by role
  if (role) {
    results = results.filter(u => u.role === role);
  }

  // Pagination
  const start = (page - 1) * limit;
  const paginated = results.slice(start, start + limit);

  return Response.json({
    success: true,
    data: paginated,
    page,
    limit,
    total: results.length,
    totalPages: Math.ceil(results.length / limit)
  });
}

REST Best Practices

  • Use nouns for resources, not verbs: /users not /get-users
  • Use HTTP methods correctly (GET for read, POST for create, etc.)
  • Return appropriate status codes
  • Keep URLs consistent and predictable
  • Use JSON for responses
  • Version your API: /api/v1/users
  • Support filtering and pagination

Key Concepts

  • REST: Standardized API design
  • Resources: Data accessible via URLs
  • Methods: GET, POST, PUT, DELETE for operations
  • Stateless: Each request is independent
  • JSON: Standard response format
