🔒 Chapter 5: Password Hashing & Security

Never store passwords as plain text! If your database is hacked, attackers get all passwords. We use hashing: a one-way encryption that can't be reversed.

Why Hash Passwords?

Bad (Plain Text) Good (Hashed)
Stored: password123 Stored: $2b$10$aB9cD2e...
If hacked: All passwords visible If hacked: Passwords unrecoverable
Never do this! Always do this!

How Bcryptjs Works

ADVOCAT-Easy uses bcryptjs, which hashes passwords securely:

import bcrypt from 'bcryptjs';

// Hashing a password
const password = 'user123!';
const hashedPassword = await bcrypt.hash(password, 10);
// Result: $2b$10$aB9cD2e3fG4hI5jK6lM7nOpQrStUvWxYzAbCdEfGhIjKlMnOpQrS

// The hash is different every time, even for same password
const hash1 = await bcrypt.hash('user123!', 10);
const hash2 = await bcrypt.hash('user123!', 10);
// hash1 !== hash2, but both match the original password

Hashing at Signup

// app/api/auth/signup/route.js
import bcrypt from 'bcryptjs';
import { users } from '@/lib/authStore';
import crypto from 'crypto';

export async function POST(request) {
  const { email, password } = await request.json();

  // Validate password strength
  if (password.length < 6) {
    return Response.json(
      { error: 'Password must be at least 6 characters' },
      { status: 400 }
    );
  }

  // Hash the password with salt rounds 10
  const hashedPassword = await bcrypt.hash(password, 10);

  // Store the hash, NOT the plain password
  const userId = crypto.randomUUID();
  users.set(userId, {
    id: userId,
    email: email,
    password: hashedPassword,  // Store hash!
    createdAt: Date.now()
  });

  return Response.json({
    success: true,
    message: 'Account created'
  });
}

Verifying at Login

// app/api/auth/login/route.js
import bcrypt from 'bcryptjs';
import { users, sessions } from '@/lib/authStore';
import crypto from 'crypto';

export async function POST(request) {
  const { email, password } = await request.json();

  // Find user by email
  const user = Array.from(users.values()).find(u => u.email === email);

  if (!user) {
    return Response.json(
      { error: 'Invalid email or password' },
      { status: 401 }
    );
  }

  // Compare plain password with hash
  const passwordValid = await bcrypt.compare(password, user.password);
  //                      ↑ plain text        ↑ stored hash

  if (!passwordValid) {
    return Response.json(
      { error: 'Invalid email or password' },
      { status: 401 }
    );
  }

  // Password is correct! Create session
  const token = crypto.randomUUID();
  sessions.set(token, {
    userId: user.id,
    createdAt: Date.now()
  });

  return Response.json({
    success: true,
    token: token
  });
}

Password Security Best Practices

  • Minimum length: At least 8 characters
  • Complexity: Uppercase, lowercase, numbers, symbols
  • Don't send in URLs: Use POST with HTTPS
  • Don't log passwords: Never console.log(password)
  • Hash with salt rounds 10+: More rounds = more secure but slower
  • Use HTTPS: Encrypt data in transit

Common Security Mistakes

// ❌ WRONG - Storing plain text
users.set(userId, {
  password: 'user123!'  // NEVER!
});

// ❌ WRONG - Using weak hash
const hash = simpleHash(password);  // Don't use simple hashing

// ✅ CORRECT - Using bcryptjs
const hash = await bcrypt.hash(password, 10);
users.set(userId, { password: hash });

Rate Limiting for Login

Prevent brute-force attacks by limiting login attempts:

// Simple rate limiting (more advanced later)
const loginAttempts = new Map();

export async function POST(request) {
  const ip = request.headers.get('x-forwarded-for') || 'unknown';

  // Check attempts from this IP
  const attempts = loginAttempts.get(ip) || 0;
  if (attempts > 5) {
    return Response.json(
      { error: 'Too many login attempts. Try again later.' },
      { status: 429 }  // Too Many Requests
    );
  }

  // Continue with login...
  loginAttempts.set(ip, attempts + 1);
}

Changing Password

export async function POST(request) {
  const { token, oldPassword, newPassword } = await request.json();

  // Validate token
  const session = sessions.get(token);
  if (!session) {
    return Response.json({ error: 'Not authenticated' }, { status: 401 });
  }

  // Get user
  const user = users.get(session.userId);

  // Verify old password
  const oldValid = await bcrypt.compare(oldPassword, user.password);
  if (!oldValid) {
    return Response.json(
      { error: 'Old password is incorrect' },
      { status: 401 }
    );
  }

  // Hash new password
  const newHash = await bcrypt.hash(newPassword, 10);
  user.password = newHash;

  return Response.json({ success: true });
}

Key Concepts

  • Hash: One-way encryption (can't reverse)
  • Salt: Random data added before hashing (makes hashes unique)
  • bcryptjs: Industry-standard for password hashing
  • Compare: Hashing plain password and comparing with stored hash
  • Round: Number of iterations (higher = more secure)
