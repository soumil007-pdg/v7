Welcome! This guide takes you from zero to building a professional SaaS application. You don't need any prior coding experience — we'll explain everything from scratch.

Prerequisites

Before we start, you'll need three things installed on your computer:

1. Node.js & npm

How to check:

node --version
npm --version

If these commands fail, download from nodejs.org (choose LTS version).

2. Git

Git is a version control system (like "track changes" for code). It lets you save snapshots of your work and collaborate with others.

How to check:

git --version

If this fails, download from git-scm.com.

3. A Code Editor

You'll write code in a text editor. We recommend VS Code (free, powerful, beginner-friendly).

Download from code.visualstudio.com.

🌐 Chapter 2: Web Foundations for Beginners

Before we jump into React and Next.js, you need to understand the three pillars of the web: HTML, CSS, and JavaScript. If you already know these, feel free to skip to Chapter 3.

HTML: The Skeleton

HTML is a markup language that structures content on a webpage. Think of it as the skeleton of a building—it defines what goes where.

Basic HTML Example

<!DOCTYPE html>
<html>
  <head>
    <title>My First Page</title>
  </head>
  <body>
    <h1>Hello, World!</h1>
    <p>This is a paragraph.</p>
    <a href="https://example.com">Click me!</a>
  </body>
</html>

Key HTML Concepts

Tags

Tags are instructions wrapped in angle brackets. Examples: <h1>, <p>, <a>.

Rule: Most tags must be closed: <p>text</p>

Attributes

Attributes add extra information to tags. Example: <a href="url"> has an href attribute.

Semantic HTML

Use meaningful tags: <header>, <nav>, <main>, <footer>. This helps search engines and assistive tech understand your page.

Common HTML Tags You'll Use

<h1>...</h1>  <!-- Headings (h1 is largest, h6 is smallest) -->
<p>...</p>    <!-- Paragraph -->
<a href="url">...</a>  <!-- Link -->
<button>...</button>  <!-- Button -->
<input />  <!-- Text input field -->
<div>...</div>  <!-- Generic container -->
<img src="url" />  <!-- Image -->

CSS: The Styling

CSS makes things look pretty. It colors text, positions elements, creates animations, and responsive designs.

CSS Basics

/* This is a CSS rule */
h1 {
  color: blue;           /* Text color */
  font-size: 24px;       /* Font size */
  text-align: center;    /* Alignment */
}

Three Ways to Use CSS

1. Inline (Bad ❌)

<h1 style="color: blue;">Hello</h1>

Don't use this—it mixes HTML and CSS, making code messy.

2. In <style> tag (Okay ✅)

<style>
  h1 { color: blue; }
</style>
<h1>Hello</h1>

Good for small pages, but not scalable.

3. External CSS file (Best ✅✅)

<link rel="stylesheet" href="styles.css">
<h1>Hello</h1>
/* In styles.css */
h1 { color: blue; }

Professional approach—separates content from styling.

CSS Selectors: Targeting Elements

/* Select all h1 tags */

/* Select element with id="header" */
#header { }

/* Select all elements with class="title" */
.title { }

/* Select h1 tags INSIDE div */
div h1 { }

/* Select all h1 AND p tags */
h1, p { }

JavaScript: The Brain

JavaScript makes webpages interactive. It responds to clicks, fetches data, and updates the page without refreshing.

JavaScript Basics

// Variables (store data)

// Functions (reusable code)

// Objects (store related data)

  name: "Alice",

The DOM (Document Object Model) is a JavaScript interface that lets you select and modify HTML elements.

⚛️ Chapter 3: React 101

React is a JavaScript library that makes building interactive user interfaces easier. Instead of manually updating the DOM, React handles it for you. Let's understand the core concepts.

What is React?

React is built on three core ideas:

1. Components

A component is a reusable JavaScript function that returns HTML (called JSX). Think of it as a recipe for a UI piece.

function Welcome() {
  return <h1>Hello, World!</h1>;
}

2. JSX

JSX is HTML-like syntax in JavaScript. It looks like HTML but is actually JavaScript.

// This is JSX:
const element = <h1 className="title">Hello</h1>;

// React converts it to JavaScript:
// const element = React.createElement("h1", {className: "title"}, "Hello");

3. Virtual DOM

React keeps a "virtual" copy of the page in memory. When state changes, React updates the virtual copy first, then efficiently updates only what changed in the real DOM. This makes apps fast.

Your First Component

// A simple component
function Button() {
  return <button>Click me</button>;
}

// Export so other files can use it
export default Button;

Components are just JavaScript functions. They take input (props) and return JSX.

Props: Passing Data to Components

Props are like function arguments—they let you customize a component.

// Define a component that accepts props
function Greeting({ name, age }) {
  return (
    <div>
      <h1>Hello, {name}!</h1>
      <p>You are {age} years old.</p>
    </div>
  );
}

// Use the component with different props
<Greeting name="Alice" age={25} />
<Greeting name="Bob" age={30} />

Key Points About Props

  • Props flow down from parent to child
  • Components can't change their own props
  • Props are read-only (immutable)

State: Making Components Interactive

State is data that a component can change. When state changes, React re-renders the component.

import { useState } from 'react';

function Counter() {
  // Declare state variable 'count' and function to change it 'setCount'
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>
        Increment
      </button>
    </div>
  );
}

export default Counter;

How useState Works

  1. useState(0) creates a state variable initialized to 0
  2. It returns an array: [currentValue, functionToChangeIt]
  3. When you call setCount(5), React updates the value and re-renders

React Hooks: Powerful Utilities

Hooks are functions that let you "hook into" React features. Here are the most common:

useState: Store and update state

const [count, setCount] = useState(0);

useEffect: Run code after render

import { useEffect } from 'react';

function App() {
  useEffect(() => {
    // This runs AFTER the component renders
    console.log("Component mounted!");

    // Fetch data
    fetch('/api/data').then(res => res.json());
  }, []);  // Empty array = run once on mount

  return <div>Hello</div>;
}

Custom Hooks: Write your own

You can create custom hooks to reuse logic across components.

// Custom hook
function useWindowWidth() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    function handleResize() {
      setWidth(window.innerWidth);
    }
    window.addEventListener('resize', handleResize);
    return () => window.removeEventListener('resize', handleResize);
  }, []);

  return width;
}

// Use it in a component
function App() {
  const width = useWindowWidth();
  return <p>Window width: {width}px</p>;
}

Real Example: Authentication Hook

In ADVOCAT-Easy, the useAuth() hook checks if a user is logged in. Here's how it works:

// hooks/useAuth.js
import { useState, useEffect } from 'react';
import { useRouter } from 'next/navigation';

export function useAuth(requireAuth = true) {
  const [isLoggedIn, setIsLoggedIn] = useState(false);
  const router = useRouter();

  useEffect(() => {
    // Check if token exists in localStorage
    const token = localStorage.getItem('sessionToken');

    if (!token) {
      // No token = not logged in
      if (requireAuth) router.push('/auth');
      return;
    }

    // Validate token with backend
    fetch('/api/auth/validate', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ token })
    })
      .then(res => res.json())
      .then(data => {
        if (data.isValid) {
          setIsLoggedIn(true);
        } else {
          // Token invalid = redirect to login
          if (requireAuth) router.push('/auth');
        }
      });
  }, []);

  return { isLoggedIn };
}

// Use it in a component
function Dashboard() {
  const { isLoggedIn } = useAuth(true);  // true = must be logged in

  if (!isLoggedIn) return <p>Loading...</p>;

  return <h1>Welcome back!</h1>;
}

Why This Pattern Matters

  • Reusable: Any component can use useAuth()
  • Clean: Logic is in one place, not scattered
  • Maintainable: Change the hook, all components update

Key React Rules

Component names start with capital letters: Button, not button
Always return a single root element (wrap in <div> if needed)
Don't call hooks inside loops or conditions—call them at the top level
Props flow down, events flow up (parent to child, child to parent via callbacks)
State is immutable—use setState, don't modify state directly

⚡ Chapter 4: Next.js 15 Deep Dive

Next.js is a React framework that makes building production-ready web apps easier. It adds routing, server-side rendering, API routes, and more. ADVOCAT-Easy uses Next.js 15 with the App Router.

What is Next.js?

Next.js solves common problems in React development:

  • Routing: Automatic routes based on file structure
  • Server & Client Components: Mix server-side and client-side rendering
  • API Routes: Write backend API endpoints as JavaScript functions
  • SEO: Automatic metadata, sitemaps, and structured data
  • Performance: Image optimization, code splitting, caching
  • Deployment: Works with Vercel and any Node.js server

The App Router: File-Based Routing

In Next.js, your folder structure automatically becomes your routes. This is the App Router (new in Next.js 13+).

app/
├── page.js              → /
├── about/page.js        → /about
├── blog/
│   ├── page.js          → /blog
│   └── [id]/page.js     → /blog/123 (dynamic)
├── api/
│   └── auth/
│       └── login/route.js → POST /api/auth/login
└── [locale]/            → /en, /hi, /mr, /te (ADVOCAT-Easy uses this)

Dynamic Routes with Brackets

Put brackets around a folder name to make it dynamic:

app/[locale]/page.js     → Matches /en, /hi, /mr, /te
app/products/[id]/page.js → Matches /products/123, /products/shoes

Access the parameter in your component:

// app/products/[id]/page.js
export default async function ProductPage({ params }) {
  const { id } = await params;  // id = "123"
  return <h1>Product {id}</h1>;
}

Server Components vs Client Components

This is the biggest change in Next.js 13+. Components are Server by default—much faster.

Server Components (Default)

// app/dashboard/page.js (this is a Server Component)
export default async function Dashboard() {
  // Run on the SERVER, not the browser
  const data = await fetchDataFromDatabase();

  return <div>{data}</div>;
}

Benefits: Fast, secure (no API keys leak), direct DB access

Limitations: Can't use hooks like useState, no interactivity

Client Components (opt-in)

// app/dashboard/DashboardClient.jsx
'use client';  // Must be FIRST line

import { useState } from 'react';

export default function DashboardClient() {
  const [count, setCount] = useState(0);

  return <button onClick={() => setCount(count + 1)}>Count: {count}</button>;
}

Benefits: Full React features, hooks, interactivity

Limitations: Runs in browser, slower than Server Components

The Pattern in ADVOCAT-Easy

ADVOCAT-Easy follows best practice: Server page wraps Client component:

// app/[locale]/dashboard/page.js (Server Component)
import DashboardClient from './DashboardClient';

export async function generateMetadata({ params }) {
  const { locale } = await params;
  return { title: 'Dashboard', description: '...' };
}

export default async function Dashboard({ params }) {
  const { locale } = await params;
  setRequestLocale(locale);  // For i18n

  return <DashboardClient />;  // Wrap the client component
}

// app/[locale]/dashboard/DashboardClient.jsx (Client Component)
'use client';

export default function DashboardClient() {
  // Interactive code here
  return <h1>Dashboard</h1>;
}

Why? Get SEO (metadata from server), translations (server-side), and interactivity (client component).

API Routes: Backend in JavaScript

Write backend endpoints in the app/api folder:

// app/api/auth/login/route.js
export async function POST(request) {
  const { email, password } = await request.json();

  // Validate user, create session
  const token = createToken();

  return new Response(
    JSON.stringify({ token }),
    { status: 200, headers: { 'Content-Type': 'application/json' } }
  );
}

Access it from the client:

'use client';

async function login(email, password) {
  const res = await fetch('/api/auth/login', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ email, password })
  });

  const { token } = await res.json();
  localStorage.setItem('sessionToken', token);
}

generateStaticParams: Pre-render All Locales

In ADVOCAT-Easy, every page exists in 4 languages (en, hi, mr, te). Use generateStaticParams to pre-render all:

// app/[locale]/layout.js
const locales = ['en', 'hi', 'mr', 'te'];

export function generateStaticParams() {
  return locales.map((locale) => ({ locale }));
}

Now every page at /en, /hi, /mr, /te is pre-rendered at build time.

Key Next.js Concepts

Folder structure = routes (app/about → /about)
Server Components (default) = fast, no JavaScript in browser
Client Components ('use client') = interactive, hooks, state
API Routes (app/api) = backend endpoints
generateMetadata = SEO titles, descriptions, Open Graph
generateStaticParams = pre-render all locales/variations

Authentication Flow

How users sign up, log in, and stay authenticated:

1. USER SIGNS UP
   ↓
   AuthClient submits email + password
   ↓
   POST /api/auth/signup
   ↓
   Server hashes password, stores in memory
   ↓
   Returns 201 Created


2. USER LOGS IN
   ↓
   AuthClient submits email + password
   ↓
   POST /api/auth/login
   ↓
   Server validates, creates UUID token, stores session
   ↓
   Returns token
   ↓
   Client stores token in localStorage


3. USER ACCESSES PROTECTED PAGE
   ↓
   useAuth() hook runs on mount
   ↓
   Checks localStorage for token
   ↓
   POST /api/auth/validate with token
   ↓
   Server validates token not expired
   ↓
   If valid: setIsLoggedIn(true)
   If invalid: router.push('/auth')


4. USER LOGS OUT
   ↓
   AuthClient calls logout()
   ↓
   POST /api/auth/logout with token
   ↓
   Server deletes session
   ↓
   Client removes token from localStorage

Data Flow: Asking a Legal Question

When a user asks a question in Quick Rights Chat:

1. User types "Can my landlord raise rent?" in GeneralQueriesClient

2. onClick handler calls handleSubmit()

3. Client sends: POST /api/chat
   {
     "message": "Can my landlord raise rent?",
     "mode": "quick",
     "token": "session-uuid"
   }

4. Server receives at app/api/chat/route.js
   - Validates token
   - Sends to Google Gemini API
   - Gemini returns legal guidance with citations

5. Server responds:
   {
     "response": "According to Property Rights Act 2012...",
     "citations": ["Property Rights Act, 2012", "Article 300A"],
     "creditsSaved": 702
   }

6. Client receives response
   - Displays AI answer with citations
   - Updates credit counter
   - Saves conversation to state

i18n (Internationalization) System

ADVOCAT-Easy works in 4 languages. Here's how:

// Server side (page.js)
import { getTranslations, setRequestLocale } from 'next-intl/server';

export async function generateMetadata({ params }) {
  const { locale } = await params;
  const t = await getTranslations({ locale, namespace: 'Auth' });

// Client side (DashboardClient.jsx)
'use client';
import { useTranslations } from 'next-intl';

export default function Dashboard() {
  const t = useTranslations('Dashboard');
  return <h1>{t('title')}</h1>;  // Displays correct language
}

The middleware redirects /dashboard → /en/dashboard (with locale prefix).

🔐 Chapter 8: Authentication System

Authentication (auth) verifies who the user is. ADVOCAT-Easy uses a simple token-based system. Let's see how it works.

How Token-Based Auth Works

SIGNUP:
  User enters email + password
    ↓
  Server hashes password (never store plain passwords!)
    ↓
  Server creates user record
    ↓
  Redirects to login

LOGIN:
  User enters email + password
    ↓
  Server checks password matches hash
    ↓
  Server creates unique token (UUID)
    ↓
  Server stores: token → {email, createdAt, expiresAt}
    ↓
  Returns token to client
    ↓
  Client stores in localStorage

ACCESSING PROTECTED PAGE:
  Page loads → useAuth() hook runs
    ↓
  Hook reads token from localStorage
    ↓
  Sends token to /api/auth/validate
    ↓
  Server checks: is token valid? Not expired?
    ↓
  If valid: page renders
  If invalid: redirects to /auth

LOGOUT:
  User clicks logout
    ↓
  Client calls /api/auth/logout with token
    ↓
  Server deletes the token from storage
    ↓
  Client removes token from localStorage

The useAuth Hook (Already Built)

ADVOCAT-Easy has a custom hook to check auth. Use it in any component:

// hooks/useAuth.js
import { useState, useEffect } from 'react';
import { useRouter } from 'next/navigation';

export function useAuth(requireAuth = true) {
  const [isLoggedIn, setIsLoggedIn] = useState(false);
  const router = useRouter();

  useEffect(() => {
    const token = localStorage.getItem('sessionToken');
    if (!token) {
      if (requireAuth) router.push('/auth');
      return;
    }

    // Validate token
    fetch('/api/auth/validate', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ token })
    })
      .then(res => res.json())
      .then(data => {
        if (data.isValid) {
          setIsLoggedIn(true);
        } else if (requireAuth) {
          router.push('/auth');
        }
      });
  }, []);

  return { isLoggedIn };
}

The Login/Signup Form (Already Built)

In ADVOCAT-Easy, AuthClient handles login. Here's the flow:

// app/[locale]/auth/AuthClient.jsx
'use client';

import { useState } from 'react';
import { useRouter } from 'next/navigation';

export default function AuthClient() {
  const [isLogin, setIsLogin] = useState(true);
  const [email, setEmail] = useState('');
  const [password, setPassword] = useState('');
  const router = useRouter();

  async function handleSubmit(e) {
    e.preventDefault();

    const endpoint = isLogin ? '/api/auth/login' : '/api/auth/signup';
    const res = await fetch(endpoint, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ email, password })
    });

    const data = await res.json();

    if (res.ok) {
      // Login/signup successful
      localStorage.setItem('sessionToken', data.token);
      router.push('/dashboard');  // Redirect to dashboard
    } else {
      // Show error
      alert(data.message);
    }
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
        placeholder="Email"
      />
      <input
        type="password"
        value={password}
        onChange={(e) => setPassword(e.target.value)}
        placeholder="Password"
      />
      <button type="submit">
        {isLogin ? 'Sign In' : 'Sign Up'}
      </button>

      <button
        type="button"
        onClick={() => setIsLogin(!isLogin)}
      >
        {isLogin ? 'Need account? Sign up' : 'Have account? Sign in'}
      </button>
    </form>
  );
}

Authentication Best Practices

Never store passwords in plain text—always hash
Use HTTPS in production (tokens leak over HTTP)
Set token expiration (ADVOCAT-Easy: 7 days)
Use httpOnly cookies for extra security (not localStorage)
Validate tokens on every protected API call
Clear localStorage on logout

🔗 Chapter 11: API Integration

APIs let your app talk to other services. ADVOCAT-Easy uses the Google Gemini API for AI, and Apify for lawyer data. Let's see how to integrate APIs safely.

What's an API?

An API (Application Programming Interface) is a contract: "Give me X data with Y parameters, I'll return Z response."

Example: Google Gemini API
  Request: { "prompt": "What is Article 21?" }
  Response: { "reply": "Article 21 protects right to life..." }

Types of APIs

REST API

Uses HTTP methods: GET (read), POST (create), PUT (update), DELETE (remove)

POST /api/chat → Ask legal question
GET /api/history → Get past questions
DELETE /api/session/123 → End session

GraphQL API

More flexible—ask for exactly what fields you need.

query {
  user(id: 123) {
    name
    email
    consultations {
      question
      answer
    }
  }
}

Calling External APIs from Next.js

From Server Components

Safe to do in server components (secrets never leak to browser):

// app/[locale]/page.js (Server Component)
async function HomePage() {
  // Call API server-side
  const res = await fetch('https://api.example.com/data', {

From Client Components (via Your Backend)

Never put API keys in client code. Instead, create a route that calls the API:

// app/api/chat/route.js (Your backend)
const GEMINI_API_KEY = process.env.GEMINI_API_KEY;  // Secret, not exposed

export async function POST(request) {
  const { message } = await request.json();

  // Call Gemini server-side
  const res = await fetch('https://api.google.com/v1/models/gemini:generateContent', {
    method: 'POST',
    headers: {
      'Content-Type': 'application/json',
      'x-goog-api-key': GEMINI_API_KEY
    },
    body: JSON.stringify({ contents: [{ parts: [{ text: message }] }] })
  });

  const geminiData = await res.json();

  return new Response(JSON.stringify({
    reply: geminiData.candidates[0].content.parts[0].text
  }), { status: 200 });
}

// app/api/chat/route.js
const GEMINI_API_KEY = process.env.GEMINI_API_KEY;

export async function POST(request) {
  const { message, mode, token } = await request.json();

  // 1. Validate user
  const isValid = await validateToken(token);
  if (!isValid) return new Response(JSON.stringify({ error: 'Unauthorized' }), { status: 401 });

  // 2. Build Gemini prompt
  const systemPrompt = `You are an expert in Indian Constitutional Law and Acts.
Provide accurate, cited legal guidance based on the Indian Constitution and relevant Acts.
Always cite the specific Article or Act section.`;

  const userPrompt = message;

  // 3. Call Gemini
  const res = await fetch('https://api.google.com/v1/models/gemini-2.5-flash:generateContent?key=' + GEMINI_API_KEY, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      contents: [{
        parts: [{ text: userPrompt }]
      }],
      systemInstruction: { parts: [{ text: systemPrompt }] },
      generationConfig: { temperature: 0.7, maxOutputTokens: 1000 }
    })
  });

  const data = await res.json();
  const answer = data.candidates[0].content.parts[0].text;

  // 4. Return response
  return new Response(JSON.stringify({
    response: answer,
    creditsSaved: 702,
    citations: extractCitations(answer)
  }), { status: 200 });
}

Always handle API failures gracefully:

async function fetchUserData(userId) {

}

💾 Chapter 13: Database & APIs

A database stores your data permanently. ADVOCAT-Easy uses in-memory storage for development, but you can add MongoDB or PostgreSQL for production.

What's a Database?

A database is organized storage that persists data across sessions.

Without DB: Data lost when server restarts
With DB: Data survives, can be queried, indexed, backed up

Types of Databases

Relational (SQL)

Example: PostgreSQL, MySQL. Data in tables with rows and columns.

-- Table: users
CREATE TABLE users (
  id INT PRIMARY KEY,
  email VARCHAR(255),
  password_hash VARCHAR(255),
  created_at TIMESTAMP
);

SELECT * FROM users WHERE email = 'alice@example.com';

Document (NoSQL)

Example: MongoDB. Data in JSON-like documents.

// Collection: users
db.users.insertOne({
  email: 'alice@example.com',
  password_hash: 'hashed...',
  created_at: new Date()
});

db.users.findOne({ email: 'alice@example.com' });

ADVOCAT-Easy: In-Memory Storage

For development, ADVOCAT-Easy uses in-memory Maps (lose data on restart):

// lib/authStore.js
const users = new Map();
const sessions = new Map();

// Create user
users.set('alice@example.com', { email: 'alice@example.com', password_hash: '...' });

// Find user
const user = users.get('alice@example.com');

// Delete user
users.delete('alice@example.com');

Adding MongoDB (Production)

Switch to MongoDB for persistent storage:

1. Install:

npm install mongodb

2. Create connection:

// lib/db.js
import { MongoClient } from 'mongodb';

const uri = process.env.MONGODB_URI;
let client = null;

async function getDb() {
  if (!client) {
    client = new MongoClient(uri);
    await client.connect();
  }
  return client.db('advocat_db');
}

export default getDb;

3. Use in API:

// app/api/auth/login/route.js
import getDb from '@/lib/db';

export async function POST(request) {
  const { email, password } = await request.json();
  const db = await getDb();

  const user = await db.collection('users').findOne({ email });

  if (!user) {
    return new Response(JSON.stringify({ message: 'User not found' }), { status: 401 });
  }

  // ... validate password, create session
}

Querying Data

Common patterns:

const db = await getDb();

// Find one
const user = await db.collection('users').findOne({ email });

// Find many
const allUsers = await db.collection('users').find({}).toArray();

// Update
await db.collection('users').updateOne(
  { _id: userId },
  { $set: { updated_at: new Date() } }
);

// Delete
await db.collection('users').deleteOne({ _id: userId });

// Count
const count = await db.collection('users').countDocuments();

Securing Data

Always hash passwords (bcryptjs)
Use indexes on frequently queried fields
Validate all input before storing
Don't expose database IDs in URLs
Backup regularly
Use environment variables for connection strings
