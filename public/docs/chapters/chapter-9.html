🌍 Chapter 9: Multilingual Support (i18n)

ADVOCAT-Easy supports 4 languages: English, हिन्दी (Hindi), मराठी (Marathi), తెలుగు (Telugu). Here's how i18n (internationalization) works.

What is i18n?

i18n = making your app work in multiple languages. It involves:

  • Translation files: Store text in each language
  • Language detection: Know which language user prefers
  • URL routing: /en, /hi, /mr, /te (locale in URL)
  • Dynamic rendering: Show correct language based on URL

Translation Files

ADVOCAT-Easy uses next-intl library. Translations are in messages/:

// messages/en.json
{
  "Auth": {
    "metaTitle": "Login or Sign Up - ADVOCAT-Easy",
    "metaDescription": "Secure login to your legal guidance account",
    "loginHeading": "Welcome back",
    "signupHeading": "Get Started"
  }
}

Using Translations

Server Components

// app/[locale]/auth/page.js
import { getTranslations } from 'next-intl/server';

export async function generateMetadata({ params }) {
  const { locale } = await params;
  const t = await getTranslations({ locale, namespace: 'Auth' });

  return {
    title: t('metaTitle')
  };
}

Client Components

// app/[locale]/auth/AuthClient.jsx
'use client';

import { useTranslations } from 'next-intl';

export default function AuthClient() {
  const t = useTranslations('Auth');

  return (
    <div>
      <h1>{t('loginHeading')}</h1>
      <p>{t('metaDescription')}</p>
    </div>
  );
}

Key i18n Concepts

messages/*.json = translation files (one per language)
Namespace = section in JSON (Auth, Dashboard, FAQ)
Server: getTranslations() for SEO metadata
Client: useTranslations() for display text
URL has locale: /en, /hi, /mr, /te
